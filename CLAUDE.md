# CLAUDE.md: standing instructions for working on Ianus

Read this first, then `INFO.md` (short overview and standing), `HANDOFF.md` (what to do next) and `PROGRESS.md` (what exists and what is verified). Repo: https://github.com/VoidR34ver/Ianus (branch `main`).

## What this is

Ianus is a 2D game engine in Rust on Bevy 0.20.1 (Rust 1.99.1), aimed at deterministic simulation games (colony sims first). GameMaker-style objects and rooms, Rust as the scripting language, an editor that will be built on Jackdaw. Owner: Zephie (student, Switzerland, writes English and German, learning Rust, limited time). You write most of the code; she directs.

## The determinism contract (do not break it)

`crates/ianus_sim` must stay: **integer maths only, no floats, no Bevy, no clocks, no OS randomness, no global state.** Same start state + same per-tick input must give bit-identical results on any machine. Consequences:

- Positions and velocities are `i32` subunits, **4096 per tile**, +y up. Tile `(tx,ty)` is centred on `(tx,ty)*4096`.
- Authored sizes are integer **hundredths of a tile** (75 = 0.75 tile). Convert with integer maths (`footprint_of`).
- Randomness only through the seeded `Rng` (xoshiro256**). Simulation systems read `TickInput`, never the keyboard.
- No `HashMap`/`HashSet` iteration, and no `sort_unstable` on non-unique keys, in any path that affects simulation state.
- Bevy systems that affect state must be explicitly ordered (the `IanusSet` chain).
- **Golden hashes** are pinned in `ianus_sim` tests (`replay_matches_golden_hash`, `walled_runs_are_repeatable_and_match_the_golden_hash`). If one changes, behaviour changed. Either it is a bug, or it is a deliberate tuning change: then update the constant and **say why in the commit/progress note**. Never update a golden just to make a test pass.
- Floats are fine only outside the sim: rendering, GUI, benchmarks.

## Commands (all headless and safe)

```text
cargo test --workspace --lib
cargo clippy --workspace --all-targets          # expected: zero warnings
cargo fmt --all
cargo build --workspace --examples               # compiles the window examples, does NOT open them
cargo run --release -p ianus_sim --example bench_hitboxes
cargo run --release -p ianus_sim --example bench_schedule
cargo run -p ianus_objects --example write_cellar   # regenerates rooms/cellar.room
```

**Opening the window (needs the owner's OK first):** `cargo run -p ianus_engine --example room`. Automated checks: env vars `IANUS_EXIT_AFTER_FRAMES`, `IANUS_SCREENSHOT`, `IANUS_SCREENSHOT_FRAME`, `IANUS_PLAY`. Screenshot late (frame 200+), not early (see the open blank-view bug in `PROGRESS.md`).

First Bevy build takes about 10 minutes (once). Later builds take seconds to a minute.

## Layout

| Path | Role |
|---|---|
| `crates/ianus_sim` | Deterministic core: movement, RNG, replay file, `Aabb`, `BroadPhase` (spatial hash), `Solids` + wall stopping, `Scheduler` (tick buckets). No Bevy. |

| `tools/quiet-run.ps1` | Launch without a console and report foreground-window changes. **Never run yet.** |

| `ianus-plan.md` | Original research and planning (market, Bevy status, risks). Partly superseded. |

Tick phases (`IanusSet`, chained in `FixedUpdate`): `Input → World → Objects → Sim → Detect`, then the tick advances. Game logic goes in `Sim`.

## Working conventions

- **Tests prove things; verify they can fail.** After writing a test for important behaviour, deliberately break the code once and confirm the test goes red, then restore. This caught two vacuous tests already.
- Fix root causes. Several bugs were found only because a test was strict (empty-grid panic, wrong empty-box claim).
- Keep `ianus_sim` and `ianus_objects` free of Bevy. Keep the runtime crate on `bevy_app/ecs/input/time/transform` sub-crates, not the `bevy` umbrella.
- `cargo fmt` reflows code. If an `Edit` fails to match text you just wrote, re-read the file region first.
- Windows: in PowerShell tool calls, refresh PATH first (`$env:Path = [Environment]::GetEnvironmentVariable("Path","Machine") + ";" + [Environment]::GetEnvironmentVariable("Path","User")`). In the Bash tool, add `$HOME/.cargo/bin`.
- This is a git repo (pushed to GitHub on 2026-11-11, one initial commit, `main`). **Commit and push only when the owner asks.** Never force-push. The owner also works from a Mac, so keep paths, scripts and tests cross-platform (`tools/quiet-run.ps1` is Windows-only by design). Files are stored with LF.
- Outside AI reviews are hypotheses: check claims against the code before acting, and say which held up (see `INFO.md`, `HANDOFF.md`).

## Known gotchas (each cost time once)

- Bevy prelude exports its own `Severity`; import ours explicitly (`use ianus::prelude::Severity;`) in files that glob both.
- `bevy_input` needs the `keyboard` feature for `KeyCode`.
- `ron` 0.12 errors carry a `span` (start/end), not a `position`.
- egui: `ctx.is_pointer_over_egui()` (not `is_pointer_over_area`); panels via `egui::Panel::{top,left,right,bottom}`.
- Bevy 0.20: `Entity::to_bits` does **not** sort in spawn order; use `entity.index()`.
- Bevy 0.20 camera: spawning with a custom `Projection` at spawn time coincided with blank rendering in some runs; the code spawns a plain `Camera2d` and edits the projection afterwards (`configure_projection`). Unconfirmed whether that was the real cause.
- `Aabb::overlaps` is exact only for **non-empty** boxes; use `overlaps_checked` if a box might be empty. `BroadPhase`/`Solids` skip empty boxes themselves.
- A `BroadPhase` must be a valid empty grid before its first rebuild (fixed; regression test exists).
- Interactive/idle bodies: `step_controlled` skips resting bodies and avoids flagging change detection; keep that property when editing it.
